## Design & Plan Docs

- Where design specs, plans, briefs and handoffs go, and whether they are committed, is the profile's call, and the session line's `design docs:` clause states it for the checkout; the repository's own instructions override it, and the hook that guards staging names both.
- A code repository's `docs/` holds reference documents: each describes current behaviour, is named for its subject rather than dated, and is updated by the change that alters that behaviour. A design spec is a decision record, not a reference document; it becomes one only by being rewritten as one, never by being left in place.
- Verify document status against the code before relying on it; update it and related docs when work lands.
